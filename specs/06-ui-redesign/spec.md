# UI 界面重构 Spec

## 背景

当前 MewCode TUI 自上而下的布局为：Header → ChatArea(`1fr`) → InputBox(固定高度 4) → StatusBar(高度 1，常驻底部) → Footer。

存在两个问题：

1. **状态栏常驻底部**，无论是否在输入、是否在流式刷新都占据一行，与目标期望的「按输入状态显隐」不符。
2. **输入框高度被写死为 4 行**（`height/min-height/max-height` 全为 4），并与边框、margin 叠加，在窄终端或小高度终端下，存在内容被裁切或控件相互遮挡的风险，缺乏「至少保证一行可见」的明确约束。

本次重构调整 TUI 布局：把状态信息移动到输入框上方，并改为按「用户是否正在输入」条件显隐；同时保证布局在各种终端尺寸下都合理、无遮挡，输入框始终至少完整显示一行。

## 目标

- 重新组织 TUI 布局，使各区域分布合理、互不遮挡。
- 状态信息显示在输入框的正上方，而非屏幕最底部。
- 状态信息按「用户是否正在输入」条件显隐：输入框有内容时显示，输入框为空（含提交后、流式刷新期间）时隐藏。
- 状态隐藏时不占据布局空间，由聊天区回收该空间，避免出现空白占位或遮挡。
- 输入框在任何终端尺寸下都至少完整显示一行输入内容，不被裁切。
- 保留现有所有状态信息字段（模型、Token 用量、性能指标、会话时长、Agent 状态、对话模式、工作目录），不丢失能力。

## 功能需求

- F1: TUI 自上而下的区域顺序为：顶部信息区 → 对话区 → 状态区 → 输入区 → 底部快捷键区，其中状态区位于输入区的正上方。
- F2: 状态区承载现有底部状态栏的全部信息内容（模型、Token 用量、性能指标、会话时长、Agent 状态、对话模式、工作目录）。
- F3: 当输入区当前有非空内容时，状态区可见。
- F4: 当输入区当前为空时，状态区隐藏。
- F5: 用户提交输入后输入区被清空，此时状态区隐藏。
- F6: 在 LLM 流式刷新（Agent 处理、流式输出）期间，只要输入区为空，状态区保持隐藏。
- F7: 状态区隐藏时不占据布局高度，其原本占据的空间由对话区回收。
- F8: 状态区由隐藏切换为显示、或由显示切换为隐藏时，其余区域（对话区、输入区）不发生内容遮挡或裁切。
- F9: 输入区在任何受支持的终端尺寸下，至少完整显示一行可编辑输入内容。
- F10: 状态区即使在隐藏期间，其内部状态信息仍持续按事件更新（如 Token、Agent 状态），以便再次显示时内容是最新的。

## 非功能需求

- N1: 布局调整不改变引擎层、工具层、Agent Loop 的任何行为，仅影响 TUI 表现层。
- N2: 现有快捷键（中断、清屏、保存、切换模型、切换模式、复制、取消、帮助）行为不变。
- N3: 现有内置命令（`/help` `/copy` `/clear` `/save` `/model` `/mode` `/quit`）行为不变。
- N4: 状态区的显隐切换响应及时，用户在输入区打字与清空时无明显延迟或闪烁。
- N5: 重构后所有既有 TUI 相关自动化测试仍通过，或被等价的新测试覆盖。
- N6: 窄终端（紧凑宽度）下，状态区沿用现有的紧凑格式策略，信息不溢出可见区域。

## 不做的事

- 不新增状态信息字段，也不改变各字段的计算方式（沿用 05-token-metrics 的指标）。
- 不修改状态栏的宽度自适应格式分级逻辑（紧凑/中等/完整三档沿用现有阈值）。
- 不引入新的输入控件能力（多行编辑、富文本、语法高亮等不在本章范围）。
- 不改变快捷键绑定与内置命令集合。
- 不改动 Header / Footer 的内容与职责。
- 不引入主题系统或配色变更。
- 不触及引擎层、适配器、工具层、会话持久化逻辑。

## 验收标准

- AC1: 启动后区域自上而下顺序为顶部信息区 → 对话区 → 状态区 → 输入区 → 底部快捷键区。（对应 F1）
- AC2: 状态区显示的字段集合与重构前底部状态栏一致。（对应 F2）
- AC3: 在输入区输入非空内容后，状态区可见。（对应 F3）
- AC4: 清空输入区内容后，状态区隐藏。（对应 F4）
- AC5: 提交一条消息后，输入区被清空且状态区隐藏。（对应 F5）
- AC6: 流式刷新期间且输入区为空时，状态区保持隐藏。（对应 F6）
- AC7: 状态区隐藏时其高度为 0，不占布局空间；对话区可用高度相应增加。（对应 F7）
- AC8: 状态区显隐切换前后，输入区始终完整可见，无任何区域被裁切或重叠。（对应 F8）
- AC9: 在最小受支持高度的终端下，输入区仍至少完整显示一行。（对应 F9）
- AC10: 状态区处于隐藏时收到 Token/Agent 状态更新事件，再次显示后内容反映最新值。（对应 F10）
- AC11: 窄终端下状态区使用紧凑格式，文本不溢出可见区域。（对应 N6）
- AC12: 重构后既有 TUI 测试套件通过，新增显隐与布局测试通过。（对应 N5）
