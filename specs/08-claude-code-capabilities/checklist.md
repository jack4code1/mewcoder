# Claude Code 能力覆盖路线 Checklist

> 每项必须通过运行测试、观察界面或检查可重复的命令结果验证。未通过的项不得标为完成，且需要把实际证据回填至 `task.md` 的进度日志。

## 文档与交付控制

- [ ] 四份阶段文档均已获批准，且任务文档反映实际状态与验证证据。（验证：检查 `spec.md`、`plan.md`、`task.md`、本文件和任务日志。）
- [ ] 实现按 P0 → P6 的依赖顺序推进，没有在权限基础完成前启用绕过网关的外部工具、Hook 或子 Agent。（验证：架构集成测试与代码审查。）
- [ ] CHANGELOG 说明交付能力、默认安全策略、配置迁移与任何兼容性影响。（验证：检查 `CHANGELOG.md` 条目。）

## P0：测试环境与密钥治理

- [ ] 在隔离环境中执行 `python -m pytest tests -q` 可完成收集，且结果已记录。（验证：命令输出。）
- [ ] 运行和开发依赖均由项目声明安装，不依赖未记录的本机包。（验证：新环境安装后执行测试收集。）
- [ ] 跟踪的配置、文档和测试数据不含真实 API 密钥、令牌或密码。（验证：敏感模式扫描与人工复核。）
- [ ] 环境变量中的模型密钥仍优先于非敏感配置，缺失凭据会显示安全错误。（验证：配置单元测试。）

## P1：权限、审批、审计与工作区隔离

- [ ] 每个内置工具都声明了稳定的操作类型与风险级别。（验证：工具元数据单元测试。）
- [ ] 项目内的相对路径和绝对路径可正常用于允许的文件工具。（验证：临时工作区测试。）
- [ ] `..`、工作区外绝对路径及符号链接逃逸均会被拒绝，且目标文件未被读取或修改。（验证：边界测试与文件内容断言。）
- [ ] 只读操作可在默认策略下执行；文件写入、编辑、命令、外部服务和管理操作进入明确的审批或拒绝流程。（验证：策略矩阵测试。）
- [ ] 用户可以分别授予单次、当前会话和当前项目许可，并能撤销；会话许可不会跨会话，项目许可不会跨项目。（验证：权限范围测试。）
- [ ] 审批界面显示操作来源、风险、资源摘要和适用时的文件 diff；不显示密钥或原始敏感参数。（验证：Textual widget 测试和审计输出检查。）
- [ ] 用户拒绝、审批超时或取消操作后，工具不执行，Agent 得到可处理的结果，界面恢复可输入状态。（验证：Agent/TUI 集成测试。）
- [ ] 所有受控执行生成审计记录，包含请求来源、判定、授权范围、结果和时间；审计记录不泄露敏感内容。（验证：审计持久化与脱敏测试。）

## P2：上下文预算、压缩与记忆

- [ ] 每次模型调用前都创建 ContextPlan，能列出纳入项、排除项、来源、优先级和预算使用。（验证：Context Planner 单元测试与 UI 查询。）
- [ ] 接近预算时系统按策略压缩低优先级历史，并保留摘要与来源的关联。（验证：长会话伪模型测试。）
- [ ] 压缩失败时，会话原始消息不丢失，并向用户报告降级状态。（验证：压缩失败测试。）
- [ ] 旧 YAML 会话可被加载，且不因缺少新的上下文元数据而失败。（验证：旧格式 fixture 测试。）
- [ ] 用户可创建、查看、更新和删除项目记忆；删除后不再被后续请求纳入。（验证：记忆 CRUD 测试。）
- [ ] 一个项目的记忆无法被其他项目的会话加载。（验证：双临时项目隔离测试。）

## P3：Skill、Slash Command 与 Hook

- [ ] 扩展目录能加载有效的项目级与应用级 Skill、命令和 Hook，并显示来源、作用域和启用状态。（验证：目录加载测试。）
- [ ] 重名或无效扩展被拒绝或禁用，并给出可理解原因。（验证：声明校验测试。）
- [ ] 既有 `/help`、`/save`、`/clear`、`/copy`、`/model`、`/mode` 和 `/quit` 在命令注册表迁移后仍可用。（验证：命令回归测试。）
- [ ] 输入框补全基于已启用命令目录，禁用命令不会出现在建议中。（验证：InputBox 测试。）
- [ ] Skill 的上下文来源和执行步骤可见，其工具操作经过同一权限与审计网关。（验证：Skill 集成测试。）
- [ ] Hook 在声明的生命周期时机运行；成功、失败、阻断、审批拒绝和取消均有可观察事件。（验证：Hook 生命周期集成测试。）

## P4：MCP 外部工具

- [ ] 用户可配置、启用、禁用和查看项目作用域内的 MCP 服务状态。（验证：MCP Manager 测试。）
- [ ] 服务可被初始化并发现工具；工具在模型可见列表中带有正确服务来源。（验证：伪 MCP 服务测试。）
- [ ] MCP 工具调用显示服务来源、输入摘要、状态与结果摘要，并经过默认审批策略。（验证：Agent/TUI 集成测试。）
- [ ] MCP 服务的连接失败、工具定义无效、调用超时和断连被转换为可恢复结果，不使本地工具或会话崩溃。（验证：故障注入测试。）
- [ ] 禁用或断连服务后，其工具不会继续暴露或执行。（验证：服务状态变更测试。）

## P5：SubAgent 与 Git Worktree

- [ ] 用户或主 Agent 可创建 SubAgent，并看到目标、状态、事件、结果与失败原因。（验证：TaskRunner 集成测试。）
- [ ] 子任务仅接收显式投影的上下文、记忆和权限，不能扩大自身许可。（验证：最小权限测试。）
- [ ] 取消一个子任务只终止该任务，不损坏主会话或其他并行任务。（验证：并行取消测试。）
- [ ] 在 Git 工作区中可为隔离写入任务创建受管 Worktree，并记录基线、分支、路径和所有者。（验证：临时 Git 仓库端到端测试。）
- [ ] 非 Git 项目、脏主工作区、创建失败和冲突均显示明确结果，不执行破坏性自动恢复。（验证：Worktree 失败路径测试。）
- [ ] 用户可查看 Worktree diff 并明确采纳或拒绝变更；拒绝不会修改主工作区。（验证：变更审查端到端测试。）
- [ ] 清理只影响系统登记的 WorktreeLease，不会删除用户目录。（验证：安全清理测试。）

## P6：Agent Teams

- [ ] 用户可定义至少两个角色的 Agent Team，并为成员分派具有依赖关系的任务。（验证：TeamCoordinator 测试。）
- [ ] 团队界面或命令可汇总成员状态、产物、审计引用和待采纳修改。（验证：团队状态集成测试。）
- [ ] 并发任务数受配置限制；相同目标文件或工作树的潜在冲突会被提示而不是自动覆盖。（验证：并发/冲突测试。）
- [ ] 团队成员产生的修改沿用 Worktree 审查与用户采纳流程。（验证：团队端到端测试。）

## 全链路验收场景

- [ ] 场景 A：安全本地修改。用户在 Git 项目中要求修改文件；Agent 读取项目文件，提交写入审批，用户查看 diff 并批准；修改落在工作区内，审计记录完整，模型继续生成最终回复。（验证：Textual 或 Agent 集成端到端测试。）
- [ ] 场景 B：拒绝危险操作。Agent 请求执行命令或访问工作区外文件；用户拒绝或策略拒绝；操作未执行、审计记录拒绝原因、会话可继续。（验证：端到端测试及文件/命令副作用断言。）
- [ ] 场景 C：长任务与记忆。长对话触发上下文压缩，用户保存项目决策并创建新会话；新会话显示并加载该项目记忆，其他项目无法读取。（验证：双项目端到端测试。）
- [ ] 场景 D：扩展与 MCP。用户启用一个 Skill、一个 Hook 与一个 MCP 服务；调用来源依次可见，所有会改变状态的调用进入审批与审计。（验证：伪 MCP/扩展端到端测试。）
- [ ] 场景 E：团队隔离交付。两名团队成员在独立 Worktree 完成子任务；系统汇总结果并标出冲突，用户仅采纳一项变更，主工作区仅包含被采纳内容。（验证：临时 Git 仓库端到端测试。）

## 回归与质量门槛

- [ ] 所有既有适配器、工具、会话、Agent Loop、指标和 TUI 测试保持通过。（验证：`python -m pytest tests -q`。）
- [ ] 新增单元、集成和端到端测试均可在无真实 API 密钥、无互联网的环境中执行。（验证：干净环境测试。）
- [ ] 配置、会话和扩展加载中的无效外部输入均被验证并显示可理解错误，而非未处理异常。（验证：参数化负向测试。）
- [ ] 每项新增用户可见能力在 README 或 MANUAL 中有可执行的说明与安全提示。（验证：文档审阅及相应场景复演。）
